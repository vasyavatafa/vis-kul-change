# Виджет попарного сравнения моделей

Самодостаточная HTML-страница по ТЗ «виджет попарного сравнения моделей»: для двух моделей и отчётной даты
показывает изменение total относительно базовой даты и факторы, которые его вызвали.

## Сборка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python build_dashboard.py --input path/to/predictions.xlsx --output dashboard.html \
    --mapper path/to/factor_mapper.xlsx
```

Скрипт читает листы `predictions` и `signals`, валидирует их, печатает проблемы в консоль и встраивает
данные как JSON. Получается один HTML-файл без внешних ресурсов (шрифты IBM Plex встроены), работает офлайн.
Все расчёты (переходы, разложение ΔT, сверка) выполняются в браузере.

| Флаг | Назначение |
| --- | --- |
| `--mapper map.xlsx` | бизнес-описания факторов: первый лист, столбцы `factor` и `factor_desc` |
| `--config cfg.json` | конфиг сборки: `factor_spark_points` (6), `total_spark_points` (24), `eps_tolerance` (1e-6), `default_model_1`, `default_model_2`, `title` |
| `--spark-points N` | окно спарклайна factor_value, в точках данных |
| `--total-spark-points N` | окно спарклайна total в блоке 1 |
| `--strict` | код возврата 1, если в данных найдены проблемы |
| `--self-test` | встроить прогон критериев приёмки (результат — плашкой вверху и в `window.__selftest`) |

Коды возврата: 0 — собрано; 1 — `--strict` и есть проблемы; 2 — собрать нельзя (нет файла/листа/столбцов).

## Описания факторов (`--mapper`)

С маппером везде — в подписях столбцов, таблицах, подсказках — вместо имени фактора показывается `factor_desc`.
Исходное имя остаётся во второй строке сводной таблицы, в подсказке и во всплывающем title. Без `--mapper`
виджет работает как раньше, на исходных именах.

Пробелы вокруг значений обрезаются. Предупреждения, без остановки сборки: фактор из данных без описания
(показывается исходное имя), пустое `factor_desc`, несколько разных описаний одного фактора (берётся первое).
Лишние строки маппера, которых нет в данных, игнорируются, поэтому можно держать один общий справочник.
Нет файла или столбцов — ошибка, код возврата 2. Пример: `make_sample_data.py --mapper-output data/factor_mapper.xlsx`.

## Что проверяется при сборке

Наличие 13 обязательных столбцов `predictions` (DATE, 6 × `*_score`, 6 × `current_*_threshold`) и 6 столбцов `signals`;
имена моделей из раздела 2; уникальность (DATE, model, factor) — дубликаты не агрегируются, берётся первая строка
и выводится список; `signal ∈ {0,1}` и непустой `weight` — иначе строка исключается; `weight ≥ 0`; постоянство
веса во времени; одинаковое `factor_value` у одноимённых факторов на дату; `total = Σ w·s`; даты signals вне
predictions; пары (дата, модель) без строк signals. Все проблемы видны и в самом виджете.

## Приёмка

```bash
.venv/bin/python make_sample_data.py --freq weekly --drop-date 2026-07-03 --output data/predictions_weekly.xlsx
.venv/bin/python build_dashboard.py --input data/predictions_weekly.xlsx --output build/selftest_weekly.html --self-test
```

Открыть HTML в браузере: плашка «Самопроверка критериев приёмки» перебирает все модели × все отчётные ×
все базовые даты (К2–К4) и выборку состояний интерфейса (К4–К6 по DOM). Критерий 7 — тот же код на недельных
данных с пропуском.

## Решения, не зафиксированные в ТЗ явно

- **«Новый» фактор с s_t = 1** стоит сразу над 0→1, а не в самом верху: иначе закрашенная часть разрывается
  и её верх перестаёт совпадать с T_t / Σw (критерий 4). «Новый» с s_t = 0 и «выбыл» — наверху, как в ТЗ.
- **Вес отсутствующей стороны** у нового/выбывшего фактора берётся с другой даты, поэтому выбывание включённого
  фактора попадает в «переключения» (−w), а не в «изменение весов».
- **Вклад в ΔT** считается как w_t·s_t − w_{t−1}·s_{t−1}; при постоянных весах это ровно w·(s_t − s_{t−1}) из ТЗ,
  а при непостоянных сумма вкладов всё равно равна ΔT. Слагаемое изменения весов показывается под столбцом,
  только если оно ненулевое.
- **Порог скрытия подписи** — по высоте: сегмент ниже 15 px (≈ 2.5% веса при 600 px) подписи не получает;
  серии из > 3 таких сегментов одного состояния объединяются в «прочие … (k)».
- **Маркеры столбца** скрываются, если не сходится ε или уровень total ≠ Σw·s на одной из дат.
- **Цвета сегментов** — по таблице раздела 8; для мелкого текста на светлом фоне используются более тёмные
  оттенки тех же цветов (как в наброске), иначе контраст недостаточен.
- **Спарклайн** расширяется влево, если вручную выбранная базовая дата раньше окна в N точек.
- В разделе 8 упомянуты «18 столбцов листа predictions», но по разделу 2 их 13 (DATE + 6 total + 6 порогов);
  проверяются эти 13, лишние столбцы игнорируются.
